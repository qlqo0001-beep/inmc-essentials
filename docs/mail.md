# 우편(mail) — 운영 안내

CMI 의 mail(send · read · clear · sendtemp) · mailall 을 대신하고, **서버의 유일한 우편함**(core `Mail` 공급처)이다.
설정 `plugins/inmc-essentials/settings/mail.yml`, 메시지 `messages/mail.yml`, 저장 DB 표 `ess_mail`(우편) · `ess_mail_keys`(받았거나 지운 열쇠 우편의 묘비).
사람끼리의 편지는 출처(origin) `inmc-essentials:letter` 로, essentials 자신이 넣는 보상(`inmc-essentials`)과 갈라 둔다 — core 우편함의 출처 걸러내기(세기·받기·초기화)에 편지가 섞이지 않게.

업적·낚시·숫자게임의 core 우편함(`data/mailbox.yml`)에 남아 있던 보상은 이 기능이 켜지는 순간 이리로 넘어오고, 그 뒤로 core 보상 서비스의
"가방이 찼다"·순위 시즌 보상·커스텀아이템/urb/던전의 못 준 지급이 전부 여기로 온다. 사람끼리의 편지도 같은 우편함에 든다.
`/숫자게임 우편함`·`/업적 우편함` 은 계속 제 몫만 보여 준다(우편의 출처로 가른다).

## 명령

| 명령 (영어 별칭) | 하는 일 | 권한 (기본) |
|---|---|---|
| `/우편` (mail) | 우편함 화면 | `inmcessentials.mail.use` (모두) |
| `/우편 받기` (claim) | 받을 것이 있는 우편을 전부 받기 | 위와 같음 |
| `/우편 읽기` (read) | 편지 목록(새것부터 번호 · 누르면 읽기 · [답장] [지우기]) | 위와 같음 |
| `/우편 읽기 <번호\|#id>` | 그 편지를 책으로 연다(읽음 표시). 목록의 클릭은 `#id 앞 8자` 를 쓴다(숫자뿐인 id 도 번호로 잘못 읽히지 않게). 보상 우편의 id 는 찾지 못한 것으로 답한다 — 보상은 우편함 화면에서 받는다 | 위와 같음 |
| `/우편 지우기 [번호\|읽은것\|전체]` (clear) | 편지 지우기. 기본 = 읽은 것. **보상과 받을 것이 남은 편지는 안 지워진다** | 위와 같음 |
| `/우편 보내기 <플레이어> <내용>` (send) | 편지(글만). 나가 있는 사람에게도 | `inmcessentials.mail.send` (모두) |
| `/우편 임시 <플레이어> <기간> <내용>` (sendtemp) | 기간(`1d` `12h` `30m`) 뒤 지워지는 편지 | 위와 같음 |
| `/우편 첨부 <플레이어> [내용]` (attach) | 손에 든 아이템을 붙여 보내기(실제로 넣었을 때만 손에서 빠진다 — 거절·저장 실패·그림자 뮤트면 손에 그대로) | `inmcessentials.mail.attach` (OP) |
| `/우편 보기 <플레이어>` (view) | 남의 우편함(받기 없음 · 편지 읽기는 읽음 표시 안 함 · Shift+우클릭으로 편지 지우기 — 받을 것이 남은 편지는 5초 안에 한 번 더 눌러야 지워지고 서버 로그에 남는다) | `inmcessentials.mail.others` (OP) |
| `/우편 비우기 <플레이어> 편지` (purge) | 그 사람의 **받을 것이 없는** 편지 지우기(첨부가 남은 편지는 남기고 몇 통인지 알려 준다) | 위와 같음 |
| `/우편 비우기 <플레이어> 편지 확인` | 첨부가 남은 편지까지 — 지운 첨부 편지는 하나하나(보낸 사람·때·아이템·돈·명령) 서버 로그에 남는다 | 위와 같음 |
| `/우편 비우기 <플레이어> 전체 확인` | 보상까지 전부 — 되돌릴 수 없어 `확인` 을 붙여야 한다(받을 것이 남은 것은 하나하나 로그에) | 위와 같음 |
| `/우편 도움` (help) | 사용법(관리 권한이 있으면 첨부·보기·비우기·우편전체도) | `.use` |
| `/우편전체 <내용>` (mailall) | 최근 `mail-all.days`(7)일 안에 들어온 모두에게 편지(나 빼고) | `inmcessentials.mail.all` (OP) |
| `/우편전체 회수` | **마지막으로 보낸** 우편전체 편지를 모두에게서 거둔다(CMI mailall remove). 그 묶음이 이미 모두 지워졌거나 만료됐으면 "거둘 것 없음"(보낸 때와 함께) — 그 전 묶음은 거두지 않는다. 거두면 보낸 때와 글 앞부분을 보여 준다 | 위와 같음 |

`inmcessentials.mail.color`(OP) — 편지 글을 MiniMessage·색으로(없으면 글자 그대로). 콘솔이 보낸 편지의 보낸 사람은 `console-sender`.

## 우편함 화면

위 45칸 = 우편(새것부터). 반짝이는 것 = 받을 것이 있거나 안 읽은 편지. 설명에 보낸 곳(플러그인)·출처·받은 때·지워지는 때·들어 있는 것(아이템 이름과 개수 · 돈 · 특전 명령 수).

- 보상: **클릭 = 그것만 받기**. 편지: **클릭 = 읽기**(책) · **우클릭 = 첨부 받기** · **Shift+우클릭 = 지우기**(받을 것이 남은 편지는 안 지워진다).
- 아래 줄: 쪽 넘기기 · **전부 받기** · 정보 · **다른 곳에서 받을 것**(기본: 경매장 받을 돈 `/경매장 미수령`, 경매장 만료 물건 `/경매장 만료` — 상점 플러그인이
  켜져 있고 PAPI `%inmcshop_auction_unclaimed_listings%`·`%inmcshop_auction_expired_listings%` 가 숫자일 때만, 개수만큼 쌓인 아이콘) · **읽은 편지 지우기**(Shift+클릭) · 닫기.
  경매장 돈·만료 물건은 여러 서버 공용 DB 의 상태 기계라 우편으로 옮기지 않는다(연구 D). 바로가기는 `shortcuts` 에서 바꾼다(최대 2개).

## 동작

- **받기 순서**(core 우편함과 같다): 아이템을 가방에 → 안 들어간 것은 그 우편에 남는다(그때는 돈·명령을 주지 않는다) → 다 들어갔으면 돈 → 이름 있는 화폐(막히면 나머지를 들고 남음,
  "돈을 주지 못해 보관합니다" 안내) → 명령(콘솔, `{player}` = 받는 사람 이름 · `%…%` = 받는 사람 기준 PAPI). 다 받은 보상은 사라지고, 편지는 글만 남는다.
  되살리지 못한 아이템은 로그에 남기고 버린다(남기면 영영 받을 수 없다 — 받는 사람에게도 알린다).
- **한도**(사용자 결정): 편지는 `letters.expire-days`(30)일 뒤 지워지고 한 사람 `letters.max-per-player`(50)통. **받을 것(첨부 아이템·돈·명령)이 남은 편지는
  만료되지 않는다** — 다 받으면 그때부터 다시 보관 일수가 돈다. 꽉 차면 기본은 **새 편지를 거절**(보낸 사람에게 "가득 찼습니다"),
  `when-full: oldest` 면 받을 것이 없는 가장 오래된 편지를 지우고 넣는다(CMI 방식). 콘솔·관리자(첨부·우편전체 권한)의 편지와 CMI 에서 가져온 편지는 꽉 차도 들어간다
  (플레이어 편지 도배로 운영 공지·보상 첨부가 막히지 않게). **보상 우편은 만료되지 않고 스스로 지우지 않는다** — 한 사람 `rewards.max-per-player`(500)통을
  넘으면 새 보상을 받지 않고 콘솔에 경고한다(넣은 쪽이 바닥에 떨구거나 제 우편함에 둔다 — core 우편함은 저장 차례마다 같은 것을 다시 넘기므로 경고는
  사람·출처·열쇠마다 **하루에 한 번**만). 편지와 보상은 따로 세므로 편지 도배로 보상이 밀려나지 않는다.
- **편지 도배 막기**: 플레이어는 편지를 보낸 뒤 `letters.send-cooldown-seconds`(10)초 동안 다시 못 보내고, 한 받는 사람에게 안 읽힌 편지를
  `letters.max-unread-per-sender`(5)통까지만 쌓을 수 있다. 콘솔·관리자는 둘 다 없다.
- **겹침**: 같은 사람·출처(플러그인)·열쇠의 우편은 한 통 — core 우편함이 서버가 죽은 뒤 같은 것을 다시 넘겨도 두 번 들어가지 않는다. **이미 받아서 지운 것도**
  30일 동안은 열쇠 묘비(`ess_mail_keys`)가 남아 다시 들어가지 않는다(받은 직후 서버가 죽어 core 우편함이 같은 것을 다시 넘기는 경우).
- **저장**: 넣기·받기·읽음·지우기마다 곧바로 DB 쓰기 줄로(30초 묶음 없음). 켤 때 전부 읽어 메모리에서 답한다. 공용 DB(mysql)면 들어오기 직전에 그 사람 것을 다시 읽는다
  — 읽는 사이에 이 서버에서 그 사람의 우편이 바뀌면(넣기·받기·지우기) 바꿔 끼우지 않고 다시 읽는다. **다시 읽기에 실패하면**(DB 끊김·시간 초과·세 번 다 바뀜)
  이 서버의 낡은 사본을 믿지 않는다 — 그 사람의 받기(`/우편 받기`·화면의 받기·다른 플러그인의 우편함 받기)를 "다른 서버와 맞추는 중" 으로 거절하고
  받으려 할 때 비동기로 다시 읽는다(성공하면 그때부터 받을 수 있다). 목록·읽기·세기는 그대로 된다.
  만료된 편지는 켤 때와 1분마다 지우고, 30일 지난 열쇠 묘비는 켤 때와 1시간마다 지운다.
- **알림**: 접속하고 `notify.join-delay-ticks` 뒤 "안 읽은 편지 N · 받을 것 M"(누르면 `/우편`) + 소리. 편지가 오면 접속 중인 받는 사람에게 알림 + 소리,
  보상이 들어오면 액션바(`notify.reward-actionbar`).
- **편지 막기**: 받는 사람이 보낸 사람을 무시하면(chat 기능의 `/무시`) "무시하고 있어 보낼 수 없습니다". 뮤트된 사람은 `letters.deny-when-muted`(기본 켬)면 못 보낸다
  — 이 값은 chat 의 `private.deny-when-muted` 와 따로다. **그림자 뮤트는 이 값과 상관없이 보낸 것처럼 보이고 넣지 않는다**(첨부는 손에 그대로 남는다).
  자기 자신에게는 못 보낸다. 글 길이 `letters.max-length`.
- 사람끼리는 **글만**(사용자 결정 — 아이템 첨부는 거래·복사 우회 통로가 된다). 첨부는 관리자 `/우편 첨부` 뿐.
- 편지 미리보기는 MiniMessage 태그를 풀고 `%` 를 전각으로 바꿔 보여 준다(남의 화면에 버튼·자리표시를 띄우지 못하게). 색 권한(`mail.color`)으로 보낸 편지와
  CMI 에서 가져온 편지도 책에서는 **색·꾸밈·그라데이션만** 살린다 — `<click>`·`<hover>`·`<insert>` 같은 태그는 글자 그대로(CMI 시절 플레이어가 쓴 태그가 읽는
  관리자의 권한으로 도는 버튼이 되지 않게). PAPI 자리표시는 풀지 않는다.
- `/우편전체` 결과는 보낸 사람 수와 함께 나를 무시해서 · 편지함이 차서 · 넣지 못해서 빠진 사람 수를 따로 알려 준다(무시는 운영 공지라도 뚫지 않는다).

## CMI 가져오기

`/에센셜 가져오기 cmi` 때 CMI 사용자의 우편(보낸 사람·시각·글)을 편지로 넣는다. 열쇠 `cmi:<시각>:<글 해시>`(시각이 없는 옛 형식은
`cmi:notime:<보낸이>:<글 해시>:<순번>` — 시각이 없다는 것도 보고에 적힌다)라 다시 가져와도 한 통이다(받는 사람이 지운 편지도 묘비가 있는 30일 동안은).
보관 일수가 지난 편지는 건너뛰고(보고에 적힘), 글이 빈 것은 "못 읽음" 으로 보고한다. **CMI 의 보관 기간(`keepFor` — sendtemp·mailall 의 4번째 칸, 초)은
그대로 만료가 된다**(`보낸 시각 + keepFor` — CMI 와 같다, 2026-10-14). 보관 기간이 없는 편지는 `letters.expire-days` 를 매긴다. 보관 칸이 숫자가 아니면 보고에 적고
기본 만료로 넣는다. CMI 글은 `&` 색이 섞여 있어 색이 있는 편지로 넣는다(색·꾸밈만 — 위 참고).
가져온 편지는 편지함 한도를 넘어서도 넣는다.

## CMI 와 다른 점

- 편지가 꽉 차면 기본은 거절(CMI 는 오래된 것을 지운다 — `when-full: oldest` 로 같게 할 수 있다). 편지 쿨타임·받는 사람마다 한도는 CMI 에 없다(편지 도배 막기).
- 받을 것이 남은 편지는 만료되지 않는다(CMI 는 첨부째 지운다).
- 보상(다른 플러그인이 넣은 것)은 만료·자동 삭제가 없다.
- `/우편 보기`·`/우편 비우기` 는 CMI 의 `-p:` 대신 따로 된 하위 명령. `/우편전체 지우기`(CMI mailall clear — 모두의 우편을 지움)는 일부러 없다. `회수` 는 마지막 묶음만 거둔다.
- 편지는 채팅 목록 대신 책으로 열린다. 받은 편지의 보낸 사람 이름은 그때의 실명이다(닉네임이 아니다 — 기록이므로).
- 번지(BungeeCord) 사이 우편 알림은 없다(공용 DB 를 쓰면 들어올 때 다시 읽는다 — 못 읽으면 받기를 막는다).
- CMI 임시 우편의 남은 기간은 가져오지 못한다(위 "CMI 가져오기").
